# GitHub checkpoint destination

Doug approved normal C use with encrypted cloud backup and automatic C restoration, zero additional spending, no replacement computer, and autonomous isolated implementation. Existing OpenCode recovery/controls are accepted; replace the destination, not their semantics. Main and live C/D remain untouched until actual acceptance. Work is in a separate branch from main; prior proof PR25 is evidence, not production code.

The destination transports only a verified encrypted Restic repository, using GitHub release drafts as uncommitted generations. Upload bounded pieces, download/hash each, upload a strict manifest, download/validate it, then publish the generation. Never delete prior generations or move a shared latest tag. Interrupted saves have no published generation or successful cloud receipt. Recovery considers published matching generations, verifies every piece and assembled archive, and refuses malformed paths/oversize payloads. A verified older generation can survive an incomplete newer one. Repository identity is explicit; credentials stay in environment. Defaults: total encrypted payload at most 8GiB, pieces at most 512MiB, manifests at most 1MiB. Limits are checked before mutating cloud state and before extraction. These are engineering limits, not unlimited free-storage entitlement.

The Windows adapter keeps the encrypted repo under DevBox Tools/CloudPersistence (already excluded from backups), and uses existing save-state/restore-state/verified-receipt routines. A cloud save succeeds only after cloud publication/readback; failure preserves the last successful receipt and blocks Finish. Startup must fetch and cryptographically verify the encrypted repo before invoking existing restore. An explicit first migration/initialization step is required; no silent blank startup if the cloud repository is missing. Existing home backend remains the default. Full Windows images, arbitrary drivers/services and all application compatibility are outside this adapter's guarantees; selected C profile paths need independent acceptance.

Tests first: interrupted upload, corrupted readback, failed publication, missing pieces, wrong generation/repository, oversized inputs, plaintext/non-Restic archives, ZIP traversal/reparse/duplicates, and intact previous generation. Actual GitHub encrypted roundtrip and Windows control/restore tests follow. Independent review precedes production activation. Checkpoint handoff after every completed part and before remote tests.

Attack: interrupt between cloud upload and publication; the previous complete generation must still restore and Finish must refuse the failed save. Source selection, locked app DB, timeout/lease/concurrency and archive inflation are reviewer focus. No live cutover is inferred from synthetic tests.
